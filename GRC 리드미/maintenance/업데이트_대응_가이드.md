# 게임 업데이트 대응 가이드

스팀이 GUNVOLT RECORDS Cychronicle을 업데이트하면 `Assembly-CSharp.dll`의 타입·필드·메서드 이름이 바뀔 수 있고,
이 모드는 그 이름들에 직접 의존합니다. 이 문서는 "업데이트됐는지 알아내기 → 무엇이 깨졌는지 좁히기 → 고치기" 순서를 정리합니다.
(2026-11-16 작성, 2026-11-20 상수 계약 확대·버전 점검 스크립트 추가. 기준 빌드는 아래 표의 값이며, 인게임 실행으로 확인한 상태가 아니라 디스크·테스트로 확인한 값입니다.)

## 검증된 기준 빌드

| 항목 | 값 | 어디서 쓰이나 |
| --- | --- | --- |
| Steam Build ID | `13530823` | `GameCompatibility.TestedBuildId` |
| `Assembly-CSharp.dll` MVID | `90b8351d-201c-4b67-8d98-87031a628c8e` | `GameCompatibility.TestedAssemblyMvid` |
| `Assembly-CSharp.dll` 크기 | 1,289,216 bytes (2025-11-13 수정본) | 참고용 |
| Unity / 백엔드 | 2021.3.31f1 / Mono | |
| MelonLoader | 0.7.3.0 (net6) | |

새 빌드로 올릴 때는 위 표와 `GameCompatibility.cs`의 두 상수, 루트 `AGENTS.md` 1절을 **같이** 고칩니다.
MVID는 `[Reflection.Assembly]::LoadFile('...\Assembly-CSharp.dll').ManifestModule.ModuleVersionId`로 읽습니다.

## 1단계: 업데이트가 일어났는지 확인

0. 게임을 켜지 않고 한 번에 보려면 `tools\check_game_version.ps1`을 돌립니다(2026-11-20 추가). 기준 값을 `GameCompatibility.cs`에서 직접 읽어
   Build ID·MVID·`AutoUpdateBehavior`·`.acf` 읽기 전용 여부를 보여 주고, 다르면 종료 코드 1을 냅니다. `test_debug.bat`도 테스트 전에 이 스크립트를 먼저 돌립니다(결과는 경고만, 테스트는 계속).

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File tools\check_game_version.ps1
   ```

1. `H:\steam\steamapps\appmanifest_2585040.acf`의 `buildid`를 위 표와 비교합니다.
2. 게임을 한 번 실행하고 MelonLoader 로그(`Latest.log`)에서 `[호환성]` 줄을 봅니다. 모드가 시작 때 스스로 점검합니다.
   - `Steam Build ID ... 검증된 빌드와 같습니다` / `점검 통과 (필드 N개, 상수 M개, 훅 클래스 전부 적용)` → 기준 빌드와 같은 환경입니다.
   - `게임이 업데이트되었을 수 있습니다`, `Assembly-CSharp가 검증본과 다릅니다` → 기준 빌드가 아닙니다.
   - `MelonLoader X가 검증 버전 0.7.3과 다릅니다` / `Unity X가 검증 버전 …과 다릅니다`(2026-11-24) → 게임 파일은 같아도 로더·엔진이 바뀌었습니다.
     MelonLoader라면 플레이 시작 로그 `BMS 노트 교체 완료`가 한 번만 찍히는지(훅 이중 적용, P4)부터 봅니다.
   - `게임 필드 불일치: <Type>.<field> - 필드 없음/타입 변경` → 이름으로 접근하는 필드가 깨졌습니다.
   - `게임 상수 불일치: <Enum>.<멤버>: 기대 X, 현재 Y/없음` → 모드가 숫자로 박아 둔 게임 enum·const 값이 바뀌었습니다. 노트 종류·방향·레인이 엉뚱하게 주입될 수 있으니 **재빌드 전에는 커스텀 곡을 플레이하지 않습니다**.
   - `커스텀 MusicID 시작 번호가 54 → N으로 바뀌었습니다` → 원본 곡이 추가되었습니다. 커스텀 곡 ID가 모두 밀리고, 예전 커스텀 기록이 남은 세이브 칸을 새 원본 곡이 물려받을 수 있습니다([알려진_문제.md](알려진_문제.md) C4).
   - `훅 적용 실패: 패치 클래스 …` / `훅 적용 실패: 크레딧 게터 …`(2026-11-23부터 시작 점검이 문제로 셈), `패치된 게임 메서드 N개`가 이전보다 줄었으면
     훅 대상 메서드가 사라졌거나 시그니처가 바뀐 것입니다. 실패한 클래스의 기능만 꺼지고 나머지는 동작합니다.
   - 플레이 중 `[호환성] <Type>.<field> 필드를 찾지 못해 이 필드를 쓰는 기능만 꺼집니다`는 그 필드를 처음 쓸 때 한 번 찍힙니다(`LazyFieldRef`).
3. 점검은 읽기 전용이고 모드 동작을 막지 않습니다. 경고가 있어도 모드는 그대로 로드됩니다.

## 2단계: 게임 없이 깨진 곳 좁히기

새 게임 파일이 설치된 상태에서 테스트만 돌려도 어디가 깨졌는지 나옵니다.

```powershell
dotnet test GRC2.Tests\GRC2.Tests.csproj
```

`GRC2.Tests/GameCompatibilityTests.cs`가 하는 일:

| 테스트 | 잡아내는 것 |
| --- | --- |
| `FieldContracts_ResolveAgainstReferencedGameAssembly` | `FieldRefAccess`로 이름 접근하는 필드가 없어졌거나 타입이 바뀜 |
| `FieldContracts_CoverEveryNamedFieldRefInSource` | 소스에 새 `LazyFieldRef<..>("이름")`(또는 `FieldRefAccess`)를 추가하고 `GameCompatibility.FieldContracts`에는 넣지 않음 |
| `ConstantContracts_MatchExpectedGameValues` | 게임의 `MusicID.SAVEABLE_ID_END`(512)·`UNIQUE_TOP`(8000), `cBGMBeatManager.defaultFrequency`(48000), 노트 변환·판정에 쓰는 `NoteTypeId`·`NoteDirectionIndex`·`NoteSubLaneType`·`NoteLaneLeftRight`·`JudgeType` 멤버 값이 바뀜 |
| `ConstantContracts_CoverEveryGameEnumMemberInSource` | 소스에서 위 게임 enum의 멤버를 새로 쓰고 `GameCompatibility.ConstantContracts`에는 넣지 않음 |
| `RuntimeLookups_ReadLoadedAssemblyAndReportMissingNames` | 상수 점검이 빌드 때 박힌 숫자가 아니라 로드된 게임 어셈블리에서 이름으로 값을 읽는지 확인 |
| `CustomMusicIdRange_StartsAfterOriginalSongsAndSkipsNamedEnumValues` | 커스텀 MusicID 시작·끝 범위와 예약 값 판정 검증 |
| `EveryPatchTarget_ResolvesInReferencedGameAssembly` | `[HarmonyPatch]`/`TargetMethod(s)`가 가리키는 게임 메서드가 없어졌거나 시그니처가 바뀜 |
| `PatchMethodParameters_MatchTargetMethodSignatures` | 패치 메서드의 매개변수 이름·타입(`__result`, `___필드` 포함)이 원본 메서드와 어긋남 |
| `CreditGetters_AllResolveOnMusicData` | `MusicData`의 크레딧 게터 7개가 모두 존재하는지 확인 |
| `TmpSettings_FallbackFontAssetsFieldResolves` | `TMP_Settings.m_fallbackFontAssets` 비공개 필드가 존재하는지 확인 |

- 게임이 다른 경로에 있으면 환경 변수 `GRC2_GAME_PATH`(테스트 어셈블리 해석)와 `-p:GamePath=...`(빌드)를 함께 지정합니다.
- 테스트 호스트에서는 Unity 내부 호출 때문에 Harmony 패치를 실제로 적용할 수 없습니다. 그래서 세 번째 테스트는 대상 해석만 검사하며,
  **대상이 존재해도 메서드 본문이 바뀌어 동작이 달라진 경우는 잡지 못합니다.** 그 부분은 인게임 확인이 필요합니다.

## 3단계: 고치는 순서

1. 테스트 실패 메시지에 나온 타입·멤버를 `Decompiled/`(로컬 디컴파일, git에 없음)나 `tools/CsSymbolTool`로 새 버전과 대조합니다.
2. 이름만 바뀐 경우: 훅/필드 이름을 새 이름으로 바꾸고 `GameCompatibility.FieldContracts`도 맞춥니다.
3. 시그니처·동작이 바뀐 경우: [HOOK_MAP.md](HOOK_MAP.md)에서 그 훅의 소유 파일과 제거 위험을 먼저 읽고, 훅의 전제(인자 순서, 반환 타입, 호출 시점)를 다시 확인합니다.
4. 새 필드를 `FieldRefAccess`로 접근하게 되면 `GameCompatibility.FieldContracts`에 한 줄을 추가합니다(안 하면 두 번째 테스트가 실패합니다).
   게임 enum 멤버를 새로 쓰면 `GameCompatibility.ConstantContracts`에 `EnumContract<타입>("멤버", 값)`을 추가합니다.
   **enum 값이 바뀐 경우에는 반드시 재빌드합니다.** C#은 enum 멤버·`const`를 모드 DLL에 숫자로 박아 두므로, 소스를 고치지 않아도 새 게임 DLL을 참조해 다시 빌드해야 새 값이 들어갑니다.
5. 빌드 후 `test_debug.bat`, 이어서 인게임에서 곡 선택 → 플레이 → 결과 → 곡 선택 복귀를 한 번 돌립니다.
6. 기준 빌드 표(위), `GameCompatibility` 상수, `AGENTS.md` 1절을 새 값으로 갱신합니다.

## 업데이트를 막고 싶을 때

- 스팀이 게임을 덮어쓰기 전에 `appmanifest_2585040.acf`를 읽기 전용으로 두고 `AutoUpdateBehavior`를 `1`(실행할 때만 업데이트)로 바꾸는 방법이 일반적입니다.
  현재 설치본은 `AutoUpdateBehavior 0`이고 `.acf`도 읽기 전용이 아닙니다([알려진_문제.md](알려진_문제.md) A5).
- 이미 업데이트된 경우 DepotDownloader로 기준 빌드의 매니페스트를 받아 되돌립니다. 이 저장소에는 그 기록이 없습니다.

## 남은 취약 지점 (고치지 않음)

- **enum·const 인라인.** 모드 코드의 `NoteTypeId.Hold`, `MusicID.UNIQUE_TOP` 같은 표현은 빌드할 때 숫자로 바뀝니다. 게임이 값을 옮기면
  이미 배포된 DLL은 예전 숫자를 계속 씁니다. 시작 점검(`ConstantContracts`)은 이름으로 런타임 값을 읽어 이 경우를 알려 주고,
  `CustomMusicIdRegistry`의 범위(`SAVEABLE_ID_END`·`UNIQUE_TOP`)만은 런타임 값을 직접 씁니다. 노트 변환은 재빌드로만 고쳐집니다.
  (2026-11-20 이전에는 점검이 `(int)MusicID.UNIQUE_TOP`처럼 코드로 값을 읽어 인라인된 숫자끼리 비교했기 때문에, 배포된 DLL에서는 게임이 바뀌어도 영원히 통과했습니다.)
- **커스텀 MusicID 이동.** ID를 외부 파일 없이 메모리에서 이름순으로 정하므로(사용자 결정, 2026-11-18) 원본 곡이 추가되거나 `hwa`의 폴더 구성이 바뀌면
  다음 실행부터 ID가 밀립니다. `BlockSave=0`으로 저장한 기록은 세이브 칸 번호를 따라가므로 다른 곡에 붙어 보일 수 있습니다. 원본 곡 추가는 시작 로그가 경고합니다.
- 게임 필드 접근은 전부 `LazyFieldRef`(처음 쓸 때 조회)입니다(2026-11-23). 필드 이름이 바뀌면 `[호환성] … 필드를 찾지 못해 이 필드를 쓰는 기능만 꺼집니다`
  경고가 한 번 남고, **그 필드를 쓰는 경로만** 꺼집니다. 예전에는 패치 클래스의 정적 초기화에서 조회해 `TypeInitializationException`으로
  같은 클래스의 다른 기능(예: 결과 화면의 제목·아트워크·난이도 전부)까지 멈췄습니다. 업데이트 뒤 로그에서 이 경고를 먼저 찾으세요.
- 문자열 이름으로 메서드를 찾는 곳은 `CreditTextPatch.TargetMethods`(`AccessTools.Method(typeof(MusicData), name)`)가 있습니다. 대상이 사라지면 해당 패치만 빠지고, 세 번째 테스트가 잡습니다.
