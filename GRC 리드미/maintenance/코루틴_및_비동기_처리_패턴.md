# 코루틴 및 비동기 처리 패턴

모드가 쓰는 코루틴을 한곳에 모아, 언제 시작하고 언제 멈추는지와 대기·타임아웃 방식을 정리합니다.
모두 `MelonCoroutines.Start/Stop`으로 돌며 게임 오브젝트 수명과 무관합니다. (2026-09-28 코드 기준)

## 패턴

### 요청 번호로 이전 요청 버리기 (`CustomBgmPlayer`)

```csharp
int requestVersion = ++_requestVersion;
CancelActiveRequest();                      // 진행 중인 UnityWebRequest.Abort()
StopPlayback();
yield return new WaitForSecondsRealtime(SelectionDebounceSeconds);
if (requestVersion != _requestVersion || !CustomAssetManager.IsCustomChartSelected())
    yield break;                            // 그 사이 다른 곡이 선택됨
```

빠르게 스크롤할 때 마지막으로 멈춘 곡만 실제로 디코딩합니다. `Cleanup()`도 번호를 올려 진행 중인 코루틴을 무효로 만듭니다.

### 같은 요청 합치기 (`CustomAssetManager`)

같은 이미지 경로에 대한 요청이 로딩 중에 또 오면 새 코루틴을 만들지 않고 콜백만 목록에 추가합니다.
대기 후 `requestedArtworkPath`가 바뀌었으면(다른 곡으로 넘어감) 디스크에서 읽지 않고 끝냅니다.

### 원본 코루틴 감싸기 (`BgmGameEndMonitor`)

`IEnumerator`를 돌려주는 원본 메서드에 postfix를 걸면, postfix는 코루틴 본문이 실행되기 **전**(열거자를 만들 때) 실행됩니다.
`ref IEnumerator __result`를 새 열거자로 바꿔 끼워, 먼저 모드 작업을 하고 원본을 `MoveNext()`로 끝까지 돌립니다.

```csharp
try
{
    while (original.MoveNext())
        yield return original.Current;
}
finally
{
    (original as IDisposable)?.Dispose();
}
```

### 프레임 수 타임아웃

`BgmLoader`와 `BgaInjector`는 "60fps 기준 프레임 수"로 타임아웃을 셉니다. 주사율이 높으면 실제 시간은 짧아집니다
([알려진_문제.md](알려진_문제.md) F).

| 대상 | 기본 | 추가 | 최대 |
|------|------|------|------|
| BGM | 600프레임 | 10MB당 60프레임 | 3600프레임 |
| BGA | 300프레임 | 100MB당 60프레임 | 3600프레임 |

### 씬 전환과 정리

- 주입 루프, BGA 준비, BGM 로드, 동기화: 결과 씬·곡 선택 씬 등에서 `StopInjection()`이 멈추고 상태를 초기화합니다.
- 프리뷰 BGM: `Cleanup()`(곡 시작, 이전 화면, 로딩/플레이 씬 진입, 원본 곡 선택).
- 아트워크 코루틴은 끝까지 돌지만, 콜백이 현재 선택된 이미지와 다르면 적용하지 않습니다.

## 새 코루틴을 추가할 때

1. 누가 시작하고 누가 멈추는지를 이 표에 적습니다.
2. 씬이 바뀌어도 도는 코루틴이면 대상 오브젝트가 파괴됐는지(`== null`) 매번 확인합니다.
3. 대기 시간은 게임 일시정지 영향을 받지 않아야 하면 `WaitForSecondsRealtime`/`unscaledDeltaTime`을 씁니다.
