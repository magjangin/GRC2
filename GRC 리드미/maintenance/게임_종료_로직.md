# 게임 종료 로직 및 모드 상호작용

곡이 언제 끝나는지를 원본 게임 코드(`Decompiled/`)로 정리하고, 모드가 어디에 끼어드는지 설명합니다.
모드 쪽 구현과 문제 해결은 [게임_종료_시간_조정_가이드.md](게임_종료_시간_조정_가이드.md)를 봅니다. (2026-09-28 기준)

## 곡 종료를 정하는 데이터

`cRythmGameManager.mRythmGameMusicData`는 `cFairyModeNotesManager.getNoteMusicData()`가 돌려주는
`FairyNoteEditorLoader.MusicData`이며, 곡을 시작할 때 `loadFairyMusicDataFromID(곡 ID)`로 읽습니다.
커스텀 곡에서는 이 곡 ID가 **템플릿 곡**이므로 템플릿 곡의 값이 들어 있습니다.

| 필드 | 단위 | 쓰임 |
|------|------|------|
| `musicFadeOutStartSample` / `musicFadeOutEndSample` | 샘플 | BGM 볼륨을 1→0으로 줄이는 구간 |
| `screenFadeOutStartSample` / `screenFadeOutEndSample` | 샘플 | 화면을 검게 덮는 구간 |
| `gameStartCheerSEStartFadeOutSample` / `…EndFadeOutSample` | 샘플 | 시작 환호성 페이드 |
| `offset` | 샘플 | 노트 시계에 더해짐 |
| BPM 목록 (`getDefaultBPM()`) | | 마디선, 홀드 연속 판정 간격 |

`musicFadeOutEndSample`은 전체 노트 수를 셀 때(`countAllJudgeNum`) "이 시점 이후 노트는 제외"하는 기준으로도 쓰입니다.

## 시작 순서 (`cRythmGameManager` 초기화 코루틴 요약)

```
requestInitialize(notesManager)          // 노트 데이터 로드, createAllNote → 모드가 노트 배열 교체
while (!notesManager.isEndInitialize()) yield
initializeScoreAndKudos()                 // countAllJudgeNum → mAllJudgeCount
… 컷인/시작 화면 연출 …
mBeatManager.requestPlayAudio()           // BGM 재생 시작
StartCoroutine(coMonitorGameEnd())        // 종료 감시 시작
```

## 종료 감시: `coMonitorGameEnd()`

1. 코루틴 **첫 줄에서** 위 페이드 샘플 값들을 지역 변수로 복사합니다. 이후 필드를 바꿔도 반영되지 않습니다.
2. 매 프레임 `currentJudgeSample = notesManager.getCurrentJudgeSample()`
   (= BGM `timeSamples` + `offset` + 옵션 판정 보정)을 봅니다.
   - 모든 노트가 판정되면(`currentAlljudgedCount == mAllJudgeCount`) 올퍼펙트 점수 보정을 한 번 실행합니다.
   - BGM 페이드 구간이면 볼륨을 줄이고, 끝 샘플을 넘으면 0으로 만듭니다.
   - 화면 페이드 구간이면 검은 화면의 알파를 올리고, 끝 샘플을 넘으면 완전히 덮습니다.
3. BGM·화면 페이드가 모두 끝나면 클리어 연출(`coPlayGameClear`)을 시작하고 결과 씬으로 넘어갑니다.
4. 실제 판정 수 합계가 `mAllJudgeCount`와 다르면 `All Note Count Invalid`를 콘솔에 남깁니다.

**곡의 끝은 노트나 BGM 길이가 아니라 페이드 샘플로 정해집니다.** 커스텀 BGM이 템플릿 곡보다 길면, 아무것도 하지 않을 때
템플릿 곡 길이에서 곡이 끝납니다.

## 모드가 끼어드는 곳

| 시점 | 모드 코드 | 하는 일 |
|------|-----------|---------|
| `createAllNote` prefix | `NoteArrayHooks` | 노트 배열 교체, 마지막 노트에 `isLast` |
| 플레이 씬 로드 | `BgmGameEndMonitor.AdjustMusicDataOnSceneLoad()` | 이전 곡의 목표 종료 시간 초기화 |
| 곡 시작 버튼 | `GameFlowHooks.StartRythmGamePrefix()` | 목표 종료 시간 초기화 |
| BGM 주입 직후 | `BgmFinishTimeManager.SetFinishTime(clip.length)` | 목표 종료 시간 = max(BGM 길이, 마지막 노트 시간) |
| `coMonitorGameEnd` postfix | `BgmGameEndMonitor.MonitorGameEndPostfix` | 원본 코루틴을 감싸서, BGM 파일이 있는 곡에서만, 목표 시간이 준비될 때까지(최대 15초) 기다린 뒤 4개 페이드 필드를 고치고 원본을 실행 |

원본 코루틴이 첫 줄에서 값을 복사하므로, 반드시 **원본의 첫 `MoveNext()` 전에** 필드를 고쳐야 합니다.
그래서 prefix로 필드만 바꾸지 않고 postfix에서 반환된 `IEnumerator`를 감쌉니다.

## 알려진 한계

- 노트 수 계산(`initializeScoreAndKudos`)은 모드의 종료 시간 보정보다 먼저 일어나므로, 템플릿 곡보다 긴 차트의 뒷부분 노트가
  전체 노트 수에서 빠집니다([알려진_문제.md](알려진_문제.md) B2).
- 마지막 노트 시간은 최상위 노트만 보고 끝 노트는 보지 않습니다(알려진 문제 B3).
- 노트 시계가 BGM 샘플 위치라 BGM은 48kHz여야 합니다(알려진 문제 B1).
