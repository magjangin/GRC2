**코드는 아직 수정하지 않았습니다.** 고칠지 여부는 실제로 써 보면서 판단하고, 고치면 해당 항목의 상태를 바꾸거나 지웁니다.

## A. 보존·부팅 (가장 먼저 볼 것)

### A1. BlockSave=1이면 세이브 파일이 없는 부팅이 무한 반복됨 — 확인됨

- 원본 `cBootSceneManageObject.coSaveInitializeGameData()`는 세이브가 없거나(`NoFile`) 깨졌을 때(`FileBroken`)
  `requestInitializedDataSave()`를 호출하고, 세이브 상태가 `Saved`가 될 때까지 **무한히 반복**합니다.
- [RecordBlockPatch.cs](../../GRC2/Harmony/RecordBlockPatch.cs)의 `RequestSavePatch`는 `BlockSave=1`(기본값)이면
  `requestGameDataSaveToFile`을 통째로 건너뜁니다. 상태가 `None`에서 바뀌지 않으므로 부팅이 끝나지 않고,
  "저장 요청 스킵" 로그가 매 프레임 찍힙니다.
- 발생 조건: 새 PC, 재설치, 세이브 삭제, **세이브 손상**(게임이 원본을 `brokenData`로 옮기고 새로 만들려 함).
- 지금은 `%USERPROFILE%\AppData\LocalLow\INTI CREATES\GUNVOLT RECORDS Cychronicle\gnrccData` 세이브가 있어 드러나지 않습니다.
- 임시 회피: 세이브가 없는 환경에서 처음 실행할 때는 `savecustomkey/config.txt`에서 `BlockSave=0`으로 두고 한 번 부팅합니다.
- 고치는 방향: `RequestSavePatch`는 세이브 파일이 없거나 깨진 부팅(`getCurrentSaveState`가 `None`인 채 부팅 씬)일 때는 저장을
  통과시킵니다. 더 근본적으로는 곡 결과 4개 필드를 이미 스냅샷으로 되돌리므로(A2), 저장 자체를 막지 않고 스냅샷 복원만
  남기는 방법이 있습니다(그 경우 `lastPlayedMusicID`/`isNew`와 플레이 수 등 `initializePreFade`가 건드리는 다른 값을 원본과 대조해야 합니다).

### A2. BlockSave=1이면 옵션 등 모든 세이브가 디스크에 남지 않음 — 확인됨

- 옵션(`optionData`)은 곡 기록과 같은 `SavableGameData`에 들어 있고, 옵션 화면(`cOptionUIUpdater`),
  메인 메뉴, 갤러리, 사운드 플레이어도 모두 같은 `requestGameDataSaveToFile`로 저장합니다.
- 따라서 `BlockSave=1` 동안 바꾼 음량·노트 속도·언어 등은 게임을 끄면 사라집니다.
  곡 결과 4개 필드(최고점/최대 콤보/플레이 수/클리어 뱃지)는 스냅샷으로 되돌리므로, 저장 차단 자체가
  결과 보호에 꼭 필요한지는 다시 검토할 여지가 있습니다.
- 고치는 방향: A1과 같습니다. 저장 차단을 "결과 씬 진입(`initializePreFade`)부터 씬 종료까지"로 좁히거나, 스냅샷 복원만 남기고
  `RequestSavePatch`를 없앱니다. 기본값이 `BlockSave=1`이라는 점도 함께 재검토하세요(기본 `AutoPlay=0`이면 보호가 덜 필요합니다).

### A3. `SteamAPI.Init` 강제 true 경로가 오히려 부팅을 멈춤 — 확인됨 (Goldberg 없을 때만)

- [SteamApiHijacker.cs](../../GRC2/Harmony/SteamApiHijacker.cs)의 `InitPostfix`는 `SteamAPI.Init()`이 false면 true로 바꿉니다.
- 원본 게임은 Init이 실패해도 로그만 남기고 계속 진행하며, `cDlcDirector.Initialize()`도 스팀 블록을 건너뛰고
  초기화를 마칩니다(그러면 모드의 DataAddon 등록 postfix도 정상 동작).
- 강제로 true가 되면 `SteamManager.Initialized`가 true가 되어 `cDlcDirector.Initialize()`가 `SteamApps.GetDLCCount()`를
  호출하고, Steamworks.NET이 `InvalidOperationException("Steamworks is not initialized.")`를 던집니다.
  - `mbInitialized`가 켜지지 않아 `sAddressableDirector.coInitialize()`의 `WaitUntil(IsInitialize)`에서 영원히 대기합니다.
  - Harmony postfix는 원본이 예외를 던지면 실행되지 않으므로 DataAddon 등록도 되지 않습니다.
- 현재 게임 폴더의 `steam_api64.dll`은 Goldberg 에뮬레이터(3.2MB, `steam_settings` 문자열 포함)라 `Init`이 성공하고,
  로그에 `SteamAPI.Init returned false`가 한 번도 없습니다. 즉 이 경로는 **실행된 적이 없고**, 스팀 업데이트나
  파일 검사로 Goldberg DLL이 원본으로 돌아가는 순간 쓰이게 됩니다.
- 고치는 방향: (1) `InitPostfix`의 강제 true를 없앱니다. 원본이 Init 실패를 이미 견디므로 가장 간단합니다(`RunCallbacks`/`Shutdown`
  건너뛰기는 `IsBypassed` 대신 `SteamManager.Initialized`로 판단). (2) 굳이 유지한다면 스팀 초기화 상태를 전제하는 호출
  (`SteamApps.GetDLCCount`, `BGetDLCDataByIndex`, `GetCurrentGameLanguage` 등)을 `IsBypassed`일 때 안전한 값으로 돌려주도록 패치합니다.
  (3) DataAddon 등록을 원본이 예외를 던져도 실행되게 하려면 postfix 대신 `[HarmonyFinalizer]`를 씁니다(H6).

### A4. 스팀·에뮬레이터 없이 첫 부팅하면 언어 조회에서 예외 — 확인됨 (원본 동작)

- 고치는 방향: `SteamApps.GetCurrentGameLanguage`를 패치해 스팀이 초기화되지 않았을 때(또는 `SteamManager.Initialized == false`)

### A5. 스팀 업데이트 차단 기능이 삭제된 상태 — 확인됨

### A6. DataAddon 등록 방식 — 확인됨 (낮음)

- `Path.GetFullPath("DataAddon")`은 **작업 폴더** 기준입니다(원본 게임도 같음). 런처나 다른 폴더의 바로가기로 실행하면 찾지 못합니다.
  모드는 절대 경로를 넣으므로 `Application.dataPath`의 상위 폴더 기준으로 바꾸면 더 안전합니다.
- 숫자 이름 폴더면 `catalog.json`이 없어도 등록합니다. 백업이 일부만 있으면 로그에 `catalog no Exist`만 남습니다.
- 참고로 `isDLCEnable`/`isUsableDlc` 강제 true는 무해합니다. 원본 `soRythmGameMusicDataMap.getSyncFromAddressable()`이
  `isExistAddressableKey()`로 한 번 더 거르므로, 파일이 없는 DLC 곡이 목록에 들어가지 않습니다.
- 고치는 방향: `Path.GetFullPath("DataAddon")` 대신 `Path.Combine(Path.GetDirectoryName(Application.dataPath), "DataAddon")`을
  씁니다(`SceneDetector`가 이미 같은 방식으로 게임 폴더를 구합니다). 그 외 등록 루프의 견고성은 H6을 봅니다.

## B. 타이밍 (게임 원본 구조와 맞물린 부분)

### B1. BGM이 48kHz가 아니면 노트가 점점 밀림 — 확인됨

- 게임의 노트 시계는 `cFairyModeNotesManager.getCurrentJudgeSample()` =
  `cBGMBeatManager.getCurrentSample()`(= BGM `AudioSource.timeSamples`) + `mNoteMusicData.offset` + 옵션의 판정 보정값입니다.
  `timeSamples`는 **BGM 파일 자체의 샘플레이트** 단위입니다.
- 모드는 `perfectSample`을 항상 48000Hz로 계산합니다([NoteSampleTime.cs](../../GRC2/Helpers/NoteSampleTime.cs)).
- 44.1kHz BGM을 넣으면 노트가 약 8.8% 늦게 판정선에 도착합니다(60초 지점에서 약 5초).
- 현재 `hwa`의 `music.ogg` 5개는 모두 48000Hz입니다. **BGM은 48kHz로 저장해야 합니다.**

### B2. 템플릿 곡의 `MusicData`가 커스텀 차트에 그대로 쓰임 — 확인 필요

- 플레이 씬의 `mNoteMusicData`(= `cRythmGameManager.mRythmGameMusicData`)는 원본 게임이
  `loadFairyMusicDataFromID(템플릿 곡 ID)`로 읽은 **템플릿 곡의 데이터**입니다.
- 커스텀 차트에도 그대로 적용되는 값:
  - `offset`: 노트 시계에 더해집니다. 템플릿 곡의 오프셋이 0이 아니면 커스텀 차트 전체가 그만큼 밀립니다.
  - 기본 BPM: 마디선(`cFairyBarLineWork`)과 홀드 연속 판정 간격(`getHoldContinueJudgeSampleInterval`) 계산에 쓰입니다.
  - `musicFadeOutEndSample`: `countAllJudgeNum()`은 이 값 이후의 노트를 전체 노트 수(`mAllJudgeCount`)에서 뺍니다.
    원본 순서상 `initializeScoreAndKudos()`(노트 수 계산)는 `requestPlayAudio()`/`coMonitorGameEnd()`보다 먼저 실행되고,
    모드의 종료 시간 보정(`BgmGameEndMonitor`)은 그 뒤 `coMonitorGameEnd` 첫 실행 때 적용됩니다(순서는 코드로 확인됨).
    따라서 **템플릿 곡보다 긴 차트는 뒷부분 노트가 전체 노트 수에서 빠집니다.** 그 결과 올퍼펙트 점수 보정
    (`currentAlljudgedCount == mAllJudgeCount`)이 곡 도중에 일어나거나, 곡 끝에 `All Note Count Invalid` 오류가 찍힐 수 있습니다.
    점수에 실제로 어떤 영향이 있는지는 게임에서 확인이 필요합니다.

### B3. 종료 시간 계산에서 끝 노트가 빠짐 — 확인됨 (낮음)

- [BgmGameEndMonitor.cs](../../GRC2/Injectors/BgmGameEndMonitor.cs)의 `GetLastNoteTime()`은 최상위 노트의 `perfectSample`만 봅니다.
  홀드/페어리의 끝 노트(`connectNodeDataArray`)가 BGM 끝보다 늦으면 잘릴 수 있습니다.

## C. 앨범·주입

### C1. BGA/BGM이 없는 앨범에 이전 앨범의 영상·음악이 들어감 — 확인됨

- [BgmBgaInjector.cs](../../GRC2/Injectors/BgmBgaInjector.cs)의 주입 루프는 현재 앨범 경로가 비어 있으면
  `_bgaFilePath`/`_bgmFilePath`를 갱신하지 않고 넘어갑니다. 직전에 플레이한 앨범(또는 `hwa` 루트)의 파일이 남습니다.
- 뿌리: `BgmBgaInjector.Initialize()`가 `hwa` 루트의 첫 mp4/오디오로 초기값을 정해 두고(앨범 스캔과 중복), 루프는
  `!string.IsNullOrEmpty(...)`일 때만 덮어씁니다.
- 고치는 방향: `Initialize()`의 폴더 스캔을 없애고, 루프에서 `_bgaFilePath = AlbumManager.GetCurrentBgaFile()`,
  `_bgmFilePath = AlbumManager.GetCurrentBgmFile()`를 **null까지 그대로** 대입합니다. 이미 있는 `!string.IsNullOrEmpty(_bgaFilePath)`
  조건이 파일 없는 앨범의 주입을 건너뜁니다.

### C2. BMS가 없거나 노트가 0개인 앨범에 이전 차트가 들어감 — 확인됨

- [SceneDetector.cs](../../GRC2/Core/SceneDetector.cs)의 `ReloadCurrentAlbumAssets()`는 새 노트가 1개 이상일 때만
  `NoteArrayHooks.UpdateBmsNotes()`를 호출하고, 현재 앨범에 BMS가 없으면 아무것도 하지 않습니다.
- 고치는 방향: `ReloadCurrentAlbumAssets`에서 노트 수와 관계없이 `UpdateBmsNotes(ParsedBmsNotes)`를 부르고(BMS가 없으면 빈 목록),
  `UpdateBmsNotes`는 빈 목록도 받아들이게 합니다(현재는 null만 거름). `TryInjectBmsNotes`는 이미 빈 목록이면 주입하지 않습니다.
  `_bmsNotes` 하나가 앨범을 가리키는 전역이라는 점이 뿌리이므로, 변환 시점에 `AlbumManager.GetCurrentBmsFile()`로 직접
  `ParsedBmsNotesByFile`을 조회하는 방법도 있습니다(H1의 곡 선택 씬 문제도 함께 풀립니다).

### C3. 키음 wav가 BGM 후보에 섞임 — 확인됨

- `.wav`가 BGM 확장자로 잡혀 로그에 앨범마다 "23개 BGM"이 찍힙니다.
- BGM은 ogg를 우선하므로 지금은 괜찮지만, ogg가 없으면 파일 시스템 순서상 `Hold end.wav` 같은 키음이 BGM으로 뽑힐 수 있습니다.
- 고치는 방향: `.wav`는 파일명이 `music`/`bgm`/`song`으로 시작할 때만 BGM 후보로 삼거나, `.wav` 후보가 여럿이면 가장 큰 파일을 고릅니다.
  또는 `info.txt`에 `bgm : 파일명` 키를 추가해 명시하게 합니다.

### C4. 커스텀 MusicID가 폴더 구성에 따라 바뀜 — 확인됨

- [MusicScrollViewHooks.cs](../../GRC2/Harmony/MusicScrollViewHooks.cs)는 앨범 딕셔너리 순회 순서대로 54, 55, …를 붙입니다.
  폴더를 추가하거나 지우면 번호가 밀려, `BlockSave=0`에서 저장된 기록과 마지막 선택 곡이 다른 곡으로 옮겨 갑니다.
- 시작 번호 54는 원본 `MusicID.DLC2_02_DATA_END`(53)의 다음 값을 직접 적은 것입니다. 게임에 곡이 추가되면 겹칩니다.
- 고치는 방향: (1) 앨범을 키(폴더 이름)로 정렬한 뒤 ID를 붙여 폴더 추가·삭제 외의 요인(딕셔너리/열거 순서)을 없앱니다.
  (2) 폴더 이름 → ID 매핑을 `hwa/`의 JSON에 저장해 폴더를 추가해도 기존 ID가 유지되게 합니다. (3) 시작 번호는
  `Enum.GetValues(typeof(MusicID))`에서 `SAVEABLE_ID_END` 미만의 최댓값 + 1로 계산하고, 원본 곡과 겹치면 경고합니다.
  (2)를 하면 `BlockSave=0`에서 저장된 기록도 폴더 구성이 바뀌어도 따라갑니다.

## D. 곡 선택 화면

### D1. 커스텀 곡 → 원본 곡으로 이동할 때 프리뷰·아트워크가 가끔 안 바뀜 — 확인 필요

- 원본 `coChangePreviewBGM()`은 `mPreviewAudioSorce.clip.name`을 null 검사 없이 읽습니다(첫 `yield` 전, 즉 `noticeChangedMusic` 안에서 동기 실행).
- [PreviewAudioManager.cs](../../GRC2/Harmony/PreviewAudioManager.cs)는 음소거를 위해 이 소스의 `clip`을 `null`로 만들고,
  복원(`RestoreMutedAudioSources`)은 `noticeChangedMusic`의 **postfix**에서 일어납니다.

## E. BMS 파서

### E1. 표준 BPM 변속 표기를 제대로 읽지 못함 — 확인됨 (현재 차트 영향 없음)

- `#BPM01 140`(표준, 콜론 없음)은 인식하지 않고 `#BPM01: 140`만 인식합니다.
- 채널 03(16진수 BPM 값을 직접 적는 채널)도 `#BPMxx` 표의 인덱스로 취급합니다.
- 채널 04/06/07(표준에서는 BGA 채널)도 BPM 변화로 해석합니다.
- 채널 02(마디 길이)와 09(STOP)는 지원하지 않습니다.
- 현재 `hwa`의 차트 5개는 모두 고정 BPM이라 영향이 없습니다.
- 고치는 방향: `#BPMxx`는 콜론 유무를 모두 받고(`^#BPM([0-9A-Za-z]{2})[:\s]\s*([0-9.]+)`), 채널 03은 16진수 값을 BPM으로 직접 읽고
  채널 08만 표를 참조하게 합니다. 채널 04/06/07은 BPM 변화로 해석하지 않습니다. 채널 02(마디 길이)를 지원하려면 마디별 길이
  배율을 `CalculateTime`의 tick 계산에 넣어야 합니다(현재 tick = 마디 + 위치가 전제).

### E2. BPM 숫자 파싱이 시스템 문화권에 의존 — 확인됨 (낮음)

- `float.Parse`를 문화권 지정 없이 씁니다. 소수점이 쉼표인 문화권에서는 `150.5`를 잘못 읽고,
  잘못된 BPM 줄 하나가 예외를 내면 차트 전체가 빈 노트로 처리됩니다.
- 고치는 방향: `float.TryParse(s, NumberStyles.Float, CultureInfo.InvariantCulture, out v)`를 쓰고, 실패하면 그 줄만 경고와 함께
  건너뜁니다(`CustomKeySettings.ParseFloat`가 이미 같은 방식입니다). 정규식 `[0-9.]+`가 `1.2.3`도 통과시키므로 TryParse가 필요합니다.

### E3. 끝 없는 홀드 시작이 다음 홀드의 끝을 공유 — 확인됨

- `HoldNoteProcessor.MatchHoldNotes()`는 이미 쓴 끝 노트를 제외하지 않습니다. 같은 레인에서 끝이 빠진 홀드 시작이 있으면
  다음 홀드의 끝과 짝이 되어, 주입이 차단되지 않고 두 홀드가 겹칩니다.
- 고치는 방향: 레인별로 tick 순으로 시작/끝을 합쳐 훑으면서 페어리(`RunPrimaryFairyMatch`)처럼 큐로 짝짓거나, 이미 짝이 된 끝을
  `HashSet`으로 제외합니다. 끝을 못 찾은 시작은 `Duration`이 0으로 남아 기존 `CheckMissingEndNotes`가 주입을 취소하므로,

### H7. 기타 코드 결함 — 확인됨 (낮음)

- `BgmLoader.LoadAndInjectAudioClip`은 `UnityWebRequest`를 `using` 없이 만들어, `StopInjection()`으로 코루틴이 로딩 중에 멈추면 요청이
  Dispose되지 않습니다(`CustomBgmPlayer`는 `using`을 씁니다).
- `GameHud`: `_latestJudgmentMs`가 곡 사이에 초기화되지 않아 다음 곡의 첫 판정 전까지 이전 곡의 마지막 마커가 보입니다.
  `Draw`가 모든 OnGUI 이벤트(Layout, 마우스 등)마다 실행되므로 `Event.current.type == EventType.Repaint`로 제한할 수 있습니다.
  `ReportJudgment`의 `judgeType` 인자는 쓰이지 않고, `BuildBarTexture`는 `SetPixel` 반복(`SetPixels32`가 더 가볍습니다)입니다.
- `CustomAssetManager.TryGetCustomArtwork`는 조회 함수인데 선택 상태(`SelectArtwork`)까지 바꿉니다. 캐시 정리(`TrimArtworkCache`)의
  보호 대상은 `requestedArtworkPath` 하나뿐이라 조회로 선택한 스프라이트는 보호되지 않습니다(앨범이 12개를 넘을 때만 잠재).
- `BgmBgaInjector.StartInjection`의 `else if (!_isPlayScene) { _isPlayScene = false; }` 분기는 아무 일도 하지 않습니다.
  `BgaInjector`의 `videoPlayer` 지역 변수는 쓰이지 않고, 씬의 활성 `VideoPlayer` **전부**에 커스텀 BGA를 넣는 것이 의도인지 확인이 필요합니다.
- `FairyNoteProcessor.ProcessFairyEndNotes`에 빈 `catch { /* ignore */ }`가 있습니다.
- `BgaBgmSyncManager`의 로그 태그가 클래스 이름과 무관합니다(`[BGAPlayerHook]`, `[BGMPlayerHook]`, `[BGABGMSyncHook]`).

### H8. 앨범 파일 "첫 번째"가 정렬되지 않은 열거 순서 — 확인됨

- `AlbumManager.AddAlbumFile`은 `Directory.EnumerateFiles` 순서대로 리스트에 넣고 `GetCurrent*File()`이 `[0]`을 씁니다.
  열거 순서는 보장되지 않습니다(NTFS는 보통 이름순). 반면 `SceneDetector.ScanAndParseBmsFiles`는 이름순으로 정렬해 파싱하므로
  두 경로가 서로 다른 파일을 가리킬 수 있습니다. 고치는 방향: 스캔 직후 각 리스트를 `StringComparer.OrdinalIgnoreCase`로 정렬합니다.
- 앨범에 이미지·BMS 등이 여럿이면 어느 것이 쓰이는지 사용자가 알 수 없습니다. 첫 번째 파일 선택 규칙과 대상 파일 이름을 로그에 남기면 좋습니다.

### H9. TextPatch의 호출당 비용 — 확인됨 (D3의 세부)

- `Text.set_text`/`TMP_Text.set_text` prefix는 게임 전체의 모든 텍스트 대입에서 실행됩니다. 스위치가 꺼져 있으면 빨리 끝나지만,
  곡 선택에서 커스텀 곡을 고르는 동안에는 켜져 있어 곡 선택 씬의 모든 대입이 `GetActiveScene().name`(문자열 할당)까지 갑니다.
  플레이 씬에서는 점수·콤보 텍스트가 바뀔 때마다 `GetCurrentMusicID()`(딕셔너리 선형 탐색)와 `GetAllOriginalTitles()`(HashSet 생성)가 실행됩니다.
- 고치는 방향: 원본 제목 집합은 `RegisterOriginalTitle`이 바뀔 때만 다시 만들어 캐시하고, 현재 앨범의 원제목은 앨범 선택 때 한 번 계산해 둡니다.
  "교체 대상 씬인가"는 `OnSceneWasLoaded`에서 bool로 캐시합니다.

### H10. 구조·중복·죽은 코드 — 확인됨 (낮음)

- 중복: 캐릭터 이름 정규화(`AlbumManager.NormalizeArtistId`와 `MusicScrollViewHooks.NormalizeCharacterName`, 아티스트_ID 문서가 이미 지적),
  `DifficultyOrder`(`MusicScrollViewHooks`, `ResultSceneUpdaterPatch`), `CalculateTimeTolerance`(Hold/Fairy가 같은 상수),
  `SAMPLE_RATE`(`JudgmentBarPatch` 48000과 `NoteSampleTime.SampleRate`), `NormalizePath`(`CustomAssetManager`, `CustomBgmPlayer`),
  폴더 스캔(`BgmBgaInjector.Initialize`와 `AlbumManager`). `RegisterArtistFirstSong`은 같은 값을 정규화 키와 원본 키로 두 번 등록합니다.
- 한 파일에 무관한 클래스가 함께 있습니다: `AudioClipPatch.cs`의 `ArtworkUpdater`, `BgmGameEndMonitor.cs`의 `BgmFinishTimeManager`,
  `BgmInjector.cs`의 `BgmSearcher`, `PlaySceneArtworkInjector.cs`의 `ArtworkImageFinder`, `NoteCreateDataBuilder.cs`의 `NoteFieldInitializer`.
  `AudioClipPatch.cs`는 이름과 달리 아트워크 반영 로직도 담습니다.
- 변환 역매핑 설계: 노트를 만들 때 `BmsNote → NoteCreateData` 사전을 함께 돌려주면 `GetBmsNoteFromNoteCreateData`, 시간 키 캐시
  (`_timeToBmsNoteCache`, 문자열 키), ±2샘플 탐색, `HoldNoteProcessor`의 키 일치·가장 가까운 시작 fallback 대부분이 필요 없어집니다
  (정상 경우는 `end.StartNote` 직접 참조 경로가 이미 처리합니다).
- 로그량: 변환 1회에 약 15줄이고 플레이당 여러 번 변환됩니다(H1). `EnableBpmLogging`/`EnableDetailedHoldNoteLogging`처럼 코드에 박힌
  `static readonly bool` 플래그를 `config.txt`의 `Verbose` 하나로 모을 수 있습니다. `getIsUsableMusicID 보정` 로그는 호출마다 찍힙니다.
- `NoteSpeedChaosPatch`의 레인 배율 딕셔너리가 `(NoteLaneLeftRight, NoteSubLaneType)` 값 튜플 키라 Mono에서 열거형 비교가 박싱될 수
  있습니다(노트당 매 프레임 조회). int 키로 바꾸면 됩니다(측정한 문제는 아닙니다).

### H11. 빌드·테스트 개선 — 확인됨 (낮음)

- `GRC2.csproj`: `GamePath` 속성을 쓰지 않고 `H:\steam\...`가 HintPath에 박혀 있습니다(F와 같은 원인). 옛 프로젝트 속성
  (`ProjectGuid`, `AppDesignerFolder`, `FileAlignment`)이 남아 있습니다. `Compile Include` 수동 목록은 "새 파일을 빠뜨려도 빌드가 통과하는"
  함정이라 README가 경고까지 합니다. `EnableDefaultCompileItems`를 켜고 목록을 지우면 사라집니다.
- `build_debug.bat`/`build_release.bat`는 거의 같은 스크립트의 복사본이고, 끝의 `timeout /t 60`이 종료 코드 전달을 60초 늦춥니다
  (인자가 있으면 생략). `SOURCE_ROOT`는 `%~dp0`로, MSBuild 탐색은 `vswhere`나 `dotnet build`로 바꿀 수 있습니다
  (`test_debug.bat`은 이미 `dotnet` CLI). 릴리스 DLL을 복사하기 전에 테스트를 돌리지 않습니다.
- 테스트:
  - `CustomKeySettingsTests`가 임시 폴더를 만들기만 하고 쓰지 않습니다 → `Initialize`/`Reload` 테스트에 쓰세요.
  - `BmsTimeCalculatorTests.CalculateTime_WithSingleBpmChange_SumsSegments`는 `t > 0`만 확인합니다. 정답은
    (1마디 @120 = 2초) + (1마디 @60 = 4초) = 6초입니다.
  - `ParseBool`의 "알 수 없는 값 → fallback"이 테스트에 없습니다.
  - `HoldNoteProcessor`/`FairyNoteProcessor`/`BmsParser.ParseBmsFile`/`SongInfoParser` 테스트가 없습니다. 파서가 `MelonLogger`를 직접 불러서
    파일 단위 테스트가 어렵습니다 → MelonLoader가 없으면 아무것도 하지 않는 얇은 로그 퍼사드를 두면 풀립니다.
- `tools/method_length_scan.py`는 중괄호를 세는 방식이고 메서드 깊이를 2로 가정해 중첩 클래스(예: `SteamApiHijacker`)와 보간·verbatim
  문자열에서 부정확합니다(스크립트 설명에도 "Not Roslyn-precise"라고 적혀 있습니다).

### H12. 시작 시 동작 — 확인됨 (낮음)

- `OnInitializeMelon`이 모든 앨범의 BMS를 동기 파싱하고 로그를 남기므로 앨범 수에 비례해 부팅이 늦어집니다. 선택할 때 파싱하는
  경로(`ReloadCurrentAlbumAssets`의 캐시 미스)가 이미 있어 지연 파싱으로 바꾸기 쉽습니다.
- 초기화 `try` 안에서 예외가 나면 `_isInitialized`가 false로 남아 `OnSceneWasLoaded`/`OnUpdate`/`OnGUI`가 모두 멈추지만, Harmony 패치는
  이미 적용된 상태라 반쪽으로 동작합니다. 단계별로 try/catch를 나누거나 실패를 `Error`로 요약하세요.
- 앨범·BMS를 추가하거나 고치면 게임을 재시작해야 합니다(문서화됨). 곡 선택 씬에 들어올 때 폴더 수정 시각을 비교해 재스캔하면
  차트를 만드는 반복이 빨라집니다. 단 C4(ID 안정화)가 선행돼야 합니다.
