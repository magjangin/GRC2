# 노트 생성 및 변환 파이프라인

파싱된 `List<BmsNote>`를 게임의 `FairyNoteEditorLoader.NoteCreateData[]`로 바꾸는 과정을 설명합니다.
모든 게임 타입은 `Assembly-CSharp.dll`을 직접 참조해 컴파일 타임에 다루며, 리플렉션은 쓰지 않습니다. (2026-09-28 코드 기준)

## 구성

| 파일 | 역할 |
|------|------|
| [BmsNoteConverter.cs](../../GRC2/Converters/BmsNoteConverter.cs) | 전체 변환 순서, 주입 취소 판단 |
| [NoteCreateDataBuilder.cs](../../GRC2/Builders/NoteCreateDataBuilder.cs) | `NoteCreateDataBuilder`: 노트 하나 생성, 역매핑 |
| [NoteFieldInitializer.cs](../../GRC2/Builders/NoteFieldInitializer.cs) | `NoteFieldInitializer`: 방향/회전 필드 설정 |
| [EnumValueHelper.cs](../../GRC2/Helpers/EnumValueHelper.cs) | BMS 값 ↔ 게임 enum 매핑 |
| [NoteSampleTime.cs](../../GRC2/Helpers/NoteSampleTime.cs) | 초 ↔ `perfectSample` |
| [HoldNoteProcessor.cs](../../GRC2/Processors/HoldNoteProcessor.cs), [FairyNoteProcessor.cs](../../GRC2/Processors/FairyNoteProcessor.cs), [NoteProcessorHelper.cs](../../GRC2/Processors/NoteProcessorHelper.cs) | 끝 노트 연결. 시간 허용 오차 계산(`CalculateTimeTolerance`)은 `NoteProcessorHelper` 한 곳에 있음 |
| [NoteArrayHooks.cs](../../GRC2/Harmony/NoteArrayHooks.cs) | `createAllNote` prefix에서 변환 결과로 배열 교체 |

## 게임의 `NoteCreateData`

`Decompiled/IntiCreates/FairyNoteEditorLoader.cs` 기준. 명시적 생성자가 없는 클래스입니다.

| 필드 | 타입 | 모드가 넣는 값 |
|------|------|----------------|
| `perfectSample` | int | `round(Time × 48000)` |
| `laneLeftRightID` | `NoteLaneLeftRight` | `Left`/`Right` |
| `subLaneID` | `NoteSubLaneType` | `Lane_1`/`Lane_2`/`Lane_3` (BMS Lane 0/1/2) |
| `noteTypeID` | `NoteTypeId` | 아래 표 |
| `directionIndex` | `NoteDirectionIndex` | 아래 표 |
| `noteSize` | `NoteSize` | `Scale1` |
| `turnDireciton` | `TurnDirection` | 페어리만 설정 (필드 이름의 오타는 원본 그대로) |
| `slideEndFlickDirection` | `NoteDirectionIndex` | `NUM` (원본 기본값과 같음) |
| `connectNodeDataArray` | `NoteCreateData[]` | 홀드/페어리의 끝 노트 |
| `isLast` | bool | 가장 늦은 노트 하나만 true |
| 그 밖의 bool, `simultaneouslyNote` | | 건드리지 않음(기본값) |

## 변환 순서 (`ConvertBmsNotesToNoteCreateData`)

1. 역매핑 캐시 초기화, `Time` 순 정렬
2. `HoldEnd`/`FairyEnd`는 따로 모으고, 나머지는 `CreateNoteCreateData()`로 변환
3. **홀드 끝 사전 검사** `CheckMissingEndNotes`: 모든 홀드 시작에 대해 `시작 + Duration`에 같은 레인의 `HoldEnd`가
   0.01초 안에 있는지 확인. 하나라도 없으면 **null 반환(주입 취소)**
4. `HoldNoteProcessor.ProcessHoldEndNotes()`: 홀드 끝을 시작의 `connectNodeDataArray`에 붙임
5. **페어리 끝 사전 검사**: `Duration > 0`인(짝이 잡힌) 페어리 시작만 같은 방식으로 확인
6. `FairyNoteProcessor.ProcessFairyEndNotes()`: 페어리 끝 연결
7. `FilterZeroTimeNotes`: `perfectSample == 0`인 노트 제거
8. **최종 검사** `CheckIncompleteConnectedNotes`: `Fairy`/`Hold` 타입인데 `connectNodeDataArray`가 비어 있는 노트가 있으면 **null 반환**
9. `SetLastNoteFlag`: 최상위 노트와 끝 노트 전체 중 `perfectSample`이 가장 큰 노트에 `isLast = true`
10. 배열로 반환

### 왜 두 번 검사하는가

원본 `cFairyModeNotesManager.createNote()`는 `Fairy`/`Hold` 노트의 `connectNodeDataArray[0]`을 null 검사 없이 읽습니다.
끝이 없는 노트가 들어가면 `createAllNote` 안에서 NullReferenceException이 나 곡 로딩이 깨집니다.

- 3·5단계는 BMS 원본 기준이라, 짝을 못 찾아 `Duration == 0`으로 남은 페어리와 매칭 단계에서 끝을 잃은 노트를 놓칩니다.
- 8단계는 실제로 게임에 넘길 배열 기준이라 그 경우까지 잡습니다.

### 주입이 취소되면

`NoteArrayHooks`는 null을 받으면 원본 `mFairyNoteCreateDataArray`를 그대로 둡니다. 곡은 멈추지 않고, **템플릿 곡의 원본 노트가
커스텀 BGM/BGA 위에서 나옵니다.** 로그에 `BMS 노트 주입이 취소되었습니다`가 찍힙니다.

## 노트 하나 만들기 (`CreateNoteCreateData`)

```csharp
var data = new NoteCreateData
{
    perfectSample = NoteSampleTime.ToSamples(bmsNote.Time),     // Math.Round(초 × 48000, AwayFromZero)
    laneLeftRightID = EnumValueHelper.GetLaneLeftRight(bmsNote.IsLeft),
    subLaneID = EnumValueHelper.GetSubLaneType(bmsNote.Lane),
    noteTypeID = EnumValueHelper.GetNoteTypeId(bmsNote.Type),
    noteSize = NoteSize.Scale1,
    slideEndFlickDirection = NoteDirectionIndex.NUM
};
var dir = NoteFieldInitializer.SetDirectionIndex(data, bmsNote);
if (bmsNote.Type == NoteType.Fairy || bmsNote.Type == NoteType.FairyEnd)
    NoteFieldInitializer.SetTurnDirection(data, dir, bmsNote);
```

### 타입

| BMS `NoteType` | `NoteTypeId` |
|----------------|--------------|
| Touch | `Touch` |
| Hold, HoldEnd | `Hold` |
| Flick | `Flick` |
| Fairy, FairyEnd | `Fairy` |

게임에는 `Boost_ButForSystem`, `Hold_Middle`도 있지만 모드는 만들지 않습니다.

### 방향 (`SetDirectionIndex`)

| 조건 | `directionIndex` |
|------|------------------|
| 페어리 끝(FairyEnd) | `CENTER_TOP` (1A/1B는 회전에만 씀) |
| 방향이 있는 노트(플릭, 페어리 시작) | Left→`LEFT_MIDDLE`, LeftUp→`LEFT_TOP`, Up→`CENTER_TOP`, RightUp→`RIGHT_TOP`, Right→`RIGHT_MIDDLE`, RightDown→`RIGHT_BOTTOM`, Down→`CENTER_BOTTOM`, LeftDown→`LEFT_BOTTOM` |
| 홀드 시작 | 레인 기준: 왼쪽 Lane 0/1/2 → `LEFT_BOTTOM`/`LEFT_MIDDLE`/`LEFT_TOP`, 오른쪽은 `RIGHT_*` |
| 그 밖(터치) | `CENTER_MIDDLE` |

### 회전 (`SetTurnDirection`, 페어리만)

| 조건 | `turnDireciton` |
|------|-----------------|
| 페어리 끝 | 1A → `Left`, 1B → `Right` |
| 페어리 시작 + 끝 노트가 연결됨 | 끝 노트의 1A/1B를 따름 |
| 그 밖 | `directionIndex`가 `LEFT_*`면 `Left`, 아니면 `Right` |

1차 페어리 매칭이 시간 계산 전에 끝나므로, 페어리 시작을 변환할 때는 보통 끝 노트가 이미 연결되어 있습니다.

## 끝 노트 붙이기 (`NoteProcessorHelper.AddEndNoteToConnectNodeArray`)

1. 끝 `BmsNote`를 `CreateNoteCreateData()`로 만든 뒤 덮어씁니다.
   - `laneLeftRightID`, `subLaneID` ← 시작 노트 값
   - `noteTypeID` ← `Hold` (홀드 끝·페어리 끝 모두)
   - `directionIndex` ← 홀드 끝 `CENTER_MIDDLE`, 페어리 끝 `CENTER_TOP`
   - `noteSize` ← `Scale1`
   - `turnDireciton`: 페어리 끝은 자기 1A/1B 값을 유지, 홀드 끝은 설정하지 않음
2. 시작 노트의 `connectNodeDataArray`를 한 칸 늘려 뒤에 붙입니다.

## 역매핑 (`GetBmsNoteFromNoteCreateData`)

`NoteCreateData`에서 원래 `BmsNote`를 찾습니다(페어리 끝 연결에서 사용).

- 키: `{시간(소수 3자리)}_{레인}_{IsLeft}_{타입}` 딕셔너리. 입력 리스트가 바뀌면(참조 비교) 다시 만듭니다.
- 키로 못 찾으면 시간 0.001초 이내 + 레인/좌우/타입이 같은 노트를 순차 검색합니다.
