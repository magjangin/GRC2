# 홀드·페어리 노트 처리 가이드

홀드(`02` 시작 / `19` 끝)와 페어리(`11`~`18` 시작 / `1A`·`1B` 끝)의 시작과 끝을 짝짓는 과정을 설명합니다.
짝짓기는 두 번 일어납니다: BMS 파싱 중(`BmsNote` 사이의 참조)과 게임 노트 변환 중(`connectNodeDataArray`).
(2026-09-28 코드 기준)

## 공통 규칙

- 시작과 끝은 **같은 레인 + 같은 좌우**(`Lane`, `IsLeft`)에 있어야 합니다.
- 끝이 없는 시작이 하나라도 있으면 그 곡의 주입이 취소됩니다([노트_생성_및_변환_파이프라인.md](노트_생성_및_변환_파이프라인.md)).
- 시간 허용 오차는 BPM에 따라 달라집니다: `허용 오차 = clamp(0.05 × 120 / BPM, 0.02, 0.15)`초.
  BPM은 파일의 `#BPM`(`BaseBpm`)을 씁니다. 예: 120 BPM → 0.05초, 240 BPM → 0.025초.

## 홀드

### 1단계: 파싱 중 짝짓기 (`HoldNoteProcessor.MatchHoldNotes`, tick 기준)

```csharp
foreach (var start in holdStarts)
{
    var end = holdEnds
        .Where(e => e.Lane == start.Lane && e.IsLeft == start.IsLeft && e.Tick > start.Tick)
        .OrderBy(e => e.Tick)
        .FirstOrDefault();
    if (end != null)
    {
        start.Duration = end.Tick - start.Tick;   // 이후 CalculateNoteTimes에서 초로 변환
        start.EndNote = end;
        end.StartNote = start;
    }
}
```

각 시작에 대해 **뒤에 오는 가장 가까운 끝**을 고릅니다. 이미 다른 시작이 쓴 끝도 다시 고를 수 있어서, 끝이 빠진 홀드 바로 뒤에
정상 홀드가 있으면 두 시작이 같은 끝을 공유합니다([알려진_문제.md](../maintenance/알려진_문제.md) E3).

### 2단계: 게임 노트에 연결 (`HoldNoteProcessor.ProcessHoldEndNotes`)

1. 변환된 노트를 `perfectSample`별로 색인합니다.
2. `Duration > 0`인 홀드 시작마다, 시작 샘플 ±2 안에서 같은 레인의 `Hold`/`Hold_Middle` 노트를 찾아
   `"{레인}_{IsLeft}_{끝 샘플}"` 키로 `holdStartMap`에 넣습니다.
3. 홀드 끝마다 다음 순서로 시작을 찾습니다.
   1. **직접 참조**: `end.StartNote`가 있으면 그 시작의 키로 찾아, 그 키에 있는 시작 노트 모두에 끝을 붙입니다.
   2. **키 일치**: 끝 노트 자신의 샘플로 만든 키에 시작이 있고 시간 차이가 허용 오차 이내면 붙입니다.
   3. **가장 가까운 시작**: 같은 레인에서 예상 끝 시간과의 차이가 허용 오차 이내인 가장 가까운 시작에 붙입니다.
4. 못 찾으면 경고 로그(해당 레인의 시작 후보와 시간 차이 포함)를 남깁니다. 끝을 못 받은 시작은 오류 로그로 남고,
   최종 검사에서 주입이 취소됩니다.

끝 노트는 시작의 레인을 물려받고, `noteTypeID = Hold`, `directionIndex = CENTER_MIDDLE`로 들어갑니다.

## 페어리

### 1단계: 1차 매칭 (`FairyNoteProcessor.MatchFairyNotes`, tick 기준)

- 레인·좌우별로 묶고 `Tick` 오름차순(같은 tick이면 시작 먼저)으로 봅니다.
- 시작은 큐에 넣고, 끝이 나오면 큐의 가장 오래된 시작과 짝짓습니다(FIFO).
- 열린 시작이 없는 끝은 건너뜁니다. 꺼낸 시작이 끝보다 늦거나 같은 tick이면 짝짓지 않습니다.

### 2단계: 2차 보정 (`FairyNoteProcessor.ReconcileFairyNotes`, 초 기준)

시간 계산이 끝난 뒤 실행합니다.

1. 잘못된 짝을 풉니다: 끝이 페어리 끝이 아님, 서로 참조가 어긋남, 레인·좌우가 다름, 끝이 시작보다 허용 오차 넘게 앞섬.
   정상인 짝은 `Duration = max(0.005초, 끝 - 시작)`으로 다시 계산합니다.
2. 짝 없는 시작마다 같은 레인의 짝 없는 끝 중에서 고릅니다.
   - 먼저 시작 기준 `-허용 오차 ~ +4초` 안에서, 시작 이후인 것 우선 → 시간 차이가 작은 것 → tick이 이른 것
   - 없으면 범위 제한 없이 같은 기준으로 강제 매칭
3. 로그: `2차 보정 완료: invalidated=…, recovered=…, forced=…`

### 3단계: 게임 노트에 연결 (`FairyNoteProcessor.ProcessFairyEndNotes`)

1. 변환된 노트 중 페어리 시작을 역매핑해 레인·좌우별 목록을 만듭니다.
2. 페어리 끝마다 시작 `BmsNote`를 정합니다: `end.StartNote`(Duration > 0) → 없으면 같은 레인에서 짝 없는 시작 중
   끝보다 (허용 오차 이상) 늦지 않은 가장 가까운 것.
3. 그 시작의 `NoteCreateData`를 찾습니다: 같은 `BmsNote` 참조 → 없으면 샘플 차이 `max(8, 허용 오차 샘플)` 이내에서 가장 가까운 것.
4. 끝을 붙입니다: `noteTypeID = Hold`, `directionIndex = CENTER_TOP`, 레인은 시작 값, 회전(`turnDireciton`)은 끝의 1A/1B 값 유지.
5. 로그: `페어리 끝 노트 처리 완료: 성공=…, 실패=…`

## 문제 해결

| 로그 | 원인과 조치 |
|------|-------------|
| `❌❌❌ BMS 노트 주입 실패: 홀드 끝 노트가 없습니다!` | `02` 뒤 같은 레인에 `19`가 없음. 목록의 `Time`, `Lane`, `IsLeft`로 위치를 찾아 `19`를 넣습니다. |
| `❌❌❌ BMS 노트 주입 실패: 페어리 끝 노트가 없습니다!` | 짝이 잡힌 페어리 시작의 예상 끝 시간에 `1A`/`1B`가 없음. |
| `❌❌❌ BMS 노트 주입 실패: 끝 노트가 연결되지 않은 노트가 있습니다!` | 짝을 아예 못 찾은 페어리 시작이 있거나 연결 단계에서 실패. `noteTypeID`, 시간, 레인이 함께 찍힙니다. |
| `홀드 끝 노트 시간 불일치` / `홀드 끝 노트 매칭 실패` | 끝 위치가 허용 오차를 넘게 어긋남. 같은 레인의 시작 후보와 차이(`Diff`)가 함께 찍힙니다. |
| 홀드 끝이 플릭으로 나옴 | 끝을 `19`가 아니라 `03`~`0A`로 찍음. 이 경우 홀드 시작의 끝이 없어져 주입이 취소됩니다. |

게임 시작 시 요약 로그(`=== BMS 파일 파싱 결과 ===`)의 `⚠️ … 끝노트가 없는 노트가 있습니다`로 미리 알 수 있습니다.
