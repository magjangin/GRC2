# 커스텀 에셋 로딩 시스템

커스텀 아트워크와 곡 선택 화면용 프리뷰 BGM을 읽어 오는 방식을 설명합니다. 플레이 중 BGM/BGA는
[BGM_BGA_관리_시스템.md](BGM_BGA_관리_시스템.md)를 봅니다. (2026-09-28 코드 기준)

## 지원 형식

| 종류 | 확장자 | 선택 규칙 |
|------|--------|-----------|
| 아트워크 | `.png`, `.jpg`, `.jpeg` | 앨범의 첫 이미지 |
| 프리뷰/플레이 BGM | `.ogg`, `.mp3`, `.wav` | `.ogg` 우선, 없으면 첫 파일 |
| BGA | `.mp4` | 앨범의 첫 mp4 |

아트워크는 리사이즈 없이 원본 해상도로 `Sprite`를 만들고(`pixelsPerUnit` 51.2), 화면 크기는 게임 UI의 `CanvasScaler`가 맞춥니다.

## 아트워크: `CustomAssetManager`

[CustomAssetManager.cs](../../GRC2/Core/CustomAssetManager.cs)

| 상태 | 설명 |
|------|------|
| `ArtworkCache` | 전체 경로 → `Sprite`, 최대 **12개**. 넘치면 오래된 것부터 `Sprite`와 `Texture2D`를 `Destroy` (현재 요청 중인 경로는 제외) |
| `PendingArtworkCallbacks` | 로딩 중인 경로 → 완료 콜백 목록 (같은 이미지 중복 요청을 하나로 합침) |
| `customArtworkSprite` | 마지막으로 선택된 스프라이트 (`GetCustomArtwork()`) |
| `isCustomChartSelected` | 커스텀 곡 선택 플래그 |

두 가지 로딩 경로가 있습니다.

- **동기 `LoadCustomArtwork(path)`**: `File.ReadAllBytes` + `Texture2D.LoadImage`. 모드 초기화 때 현재 앨범 이미지를 미리 읽는 데만 씁니다.
- **비동기 `RequestCustomArtwork(path, onLoaded)`**: 곡 선택 화면용.
  1. 캐시에 있으면 바로 콜백
  2. 0.08초 대기(연속 스크롤 중 지나간 곡은 읽지 않음). 그 사이 다른 이미지가 요청되면 취소
  3. `UnityWebRequestTexture.GetTexture(file:///…, nonReadable: true)`로 읽고 캐시에 넣은 뒤 콜백

주입 스위치:

- `IsSceneWhereInjectionDisallowed()`: 현재 씬이 `SoundPlayerScene` 또는 `MoviePlayer_MovieSelect`면 true
- `ShouldInjectCustomContent()`: 위가 false이고 커스텀 곡이 선택된 상태면 true. BMS/BGM/BGA 주입과 곡 종료 보정이 모두 이 값을 봅니다.

## 아트워크를 적용하는 곳

| 화면 | 코드 | 방식 |
|------|------|------|
| 곡 선택 큰 아트워크 | [ArtWorkPatch.cs](../../GRC2/Harmony/ArtWorkPatch.cs) | `cMusicSelectArtWork.requestSetArtworkSprite` prefix에서 `useSprite`를 캐시된 커스텀 스프라이트로 교체. 캐시에 없으면 비동기 요청만 시작 |
| 곡 선택 (로드 완료 후) | `ArtworkUpdater` ([ArtworkUpdater.cs](../../GRC2/Harmony/ArtworkUpdater.cs)) | 비동기 로드가 끝나면 `mArtWorkAndMusicDetail.mArtWork.requestSetArtworkSprite(sprite, true)` 호출 |
| 곡 시작 창 | `GameFlowHooks.PreMusicStartWindowOpenedPostfix` | `requestOpenWindow` postfix에서 `mArtworkImage.sprite` 교체 |
| 플레이 씬 | [PlaySceneArtworkInjector.cs](../../GRC2/Core/PlaySceneArtworkInjector.cs) | 아래 참고 |
| 결과 씬 | `ResultSceneUpdaterPatch` | `initializePreFade` 이후 `isAbleFadeOpenOnSceneStart()`가 true가 될 때까지(최대 10초) 기다렸다가 `mArtWorkImage.sprite` 교체 |

### 플레이 씬 (`PlaySceneArtworkInjector`)

- 플레이 씬 진입 때 `SceneDetector`가 `StartArtworkInjection()`을 호출합니다.
- 게임 타입이 소유하지 않는 오브젝트라 이름으로 찾습니다([ArtworkImageFinder.cs](../../GRC2/Core/ArtworkImageFinder.cs)):
  `GameObject.Find("ArtWork")` → 각 루트의 `Transform.Find("ArtWork")` → 모든 `Image` 중 이름이 `ArtWork`(대소문자 무시)인 것.
  찾은 `Image`는 씬별로 캐시합니다.
- 즉시 한 번 넣어 보고(`ApplyArtworkImmediately()`), 0.05초 뒤 코루틴에서 한 번 더 넣습니다(게임이 나중에 덮어쓰는 경우 대비).
  즉시 적용은 결과를 돌려주지 않고 코루틴은 항상 실행됩니다(예전 `TryInjectArtworkImmediately()`는 항상 false를 반환하는 죽은 분기였습니다).

## 프리뷰 BGM: `CustomBgmPlayer`

[CustomBgmPlayer.cs](../../GRC2/Harmony/CustomBgmPlayer.cs), 커스텀 곡으로 커서가 갈 때 `AudioClipPatch`가 시작합니다.

1. 같은 파일이 이미 재생 중이면 아무것도 하지 않습니다.
2. 진행 중인 요청을 취소하고 재생을 멈춘 뒤 **0.15초** 기다립니다(휠·키를 빠르게 넘길 때 디코딩 방지).
3. 최근 **3개** 클립 캐시에 있으면 바로 재생합니다.
4. 없으면 `UnityWebRequestMultimedia.GetAudioClip(file:///…, AudioType.UNKNOWN)`에 `streamAudio = true`로 읽습니다.
5. `DontDestroyOnLoad`된 `CustomPreviewBGM` 오브젝트의 `AudioSource`(루프, 우선순위 0, 볼륨 1)로 재생합니다.

정리 시점: 원본 곡 선택, 곡 시작(`startRythmGame`), 이전 화면(`backToPreScreen`), 로딩/플레이 씬 진입.

### 원본 프리뷰 음소거 (`PreviewAudioManager`)

- `cMusicSelectSceneUIUpdater`의 `mPreviewAudioSorce`/`mAmbientAudioSorce`만 대상으로 합니다(씬 전체 검색 없음).
- 음소거 방법: `Stop()` + `volume = 0` + `clip = null`. **`mute = true`는 쓰지 않습니다.** 게임의 `sSoundManager2D`는
  `clip == null`인 슬롯을 빈 슬롯으로 재사용하는데, `mute`를 되돌리는 원본 코드가 없어서 그 슬롯을 넘겨받은 판정 효과음 등이
  영구히 무음이 되기 때문입니다.
- 원본이 프리뷰를 늦게 다시 틀 수 있어 2초 동안 0.1초마다 다시 음소거합니다. 그 사이 슬롯이 다른 소리에 넘어가면 건드리지 않습니다.
- 원본 곡으로 돌아가면 저장해 둔 볼륨·clip을 되돌립니다.
