# 앨범 관리 시스템 분석

`hwa` 폴더의 앨범(곡 폴더)을 스캔하고, 곡 선택 화면의 커스텀 MusicID와 앨범을 연결하는
[`AlbumManager`](../../GRC2/Core/AlbumManager.cs)를 설명합니다. (2026-09-28 코드 기준)

## 폴더 구조

```
<게임 폴더>/
└── hwa/
    ├── shut up/            → 앨범 키 "shut up"
    │   ├── hwa2.bms        (차트, .bms/.bme/.bml)
    │   ├── Thumbnail.png   (아트워크, .png/.jpg/.jpeg)
    │   ├── video.mp4       (BGA)
    │   ├── music.ogg       (BGM, .ogg/.mp3/.wav — ogg 우선)
    │   ├── info.txt        (곡 정보, 첫 번째 .txt 하나만)
    │   └── *.wav           (키음. BGM 후보에도 잡힘 → 알려진 문제 C3)
    └── (hwa 루트 파일)      → 앨범 키 "root"
```

- `hwa` 폴더는 모드 초기화 때 없으면 만듭니다(`SceneDetector.OnInitializeMelon`).
- 하위 폴더 하나가 앨범 하나입니다. 더 깊은 폴더는 보지 않습니다(`TopDirectoryOnly`).
- `hwa` 루트 자체도 앨범("root")으로 등록합니다. 루트에 파일이 없으면 등록되지 않습니다.
- 파일이 하나라도 있으면 앨범으로 등록합니다. BMS가 없어도 등록됩니다.
- 같은 종류의 파일이 여러 개면 **첫 번째 파일**만 씁니다(BGM만 ogg 우선). "첫 번째"는 `Directory.EnumerateFiles` 순서이고
  `AlbumManager`는 정렬하지 않습니다(`SceneDetector`는 파싱할 때만 이름순으로 정렬). 같은 종류를 하나만 두는 것이 안전합니다
  ([알려진_문제.md](../maintenance/알려진_문제.md) H8).

## 데이터 구조

```csharp
public class AlbumInfo
{
    public string AlbumFolderPath { get; set; }
    public string AlbumName { get; set; }          // 폴더 이름
    public List<string> BmsFiles { get; set; }
    public List<string> ImageFiles { get; set; }
    public List<string> BgaFiles { get; set; }
    public List<string> BgmFiles { get; set; }
    public string TxtFile { get; set; }
    public SongInfo SongInfo { get; set; }         // info.txt 파싱 결과
}
```

`AlbumManager`의 내부 상태:

| 필드 | 타입 | 용도 |
|------|------|------|
| `_albums` | `Dictionary<string, AlbumInfo>` | 앨범 키 → 앨범 |
| `_currentAlbum` | `AlbumInfo` | 현재 선택된 앨범 |
| `_musicIdToAlbumMap` | `Dictionary<MusicID, AlbumInfo>` | 커스텀 MusicID → 앨범 |
| `_musicIdToOriginalTitleMap` | `Dictionary<MusicID, string>` | 템플릿 곡 ID → 원본 제목 (TextPatch용) |
| `_artistIdToFirstSong` | `Dictionary<string, (MusicID, string)>` | 캐릭터 → 그 캐릭터의 첫 원본 곡 |

`MusicID`는 게임의 `soRythmGameMusicDataMap.MusicID` enum입니다.

## info.txt 형식

[`SongInfoParser`](../../GRC2/Parsers/SongInfoParser.cs)가 읽습니다. 각 줄은 `키 구분자 값` 형식이며,
구분자는 `:`, `=`, `：`, 공백 중 하나입니다. 키 앞의 `#`은 있어도 되고, `//` 뒤는 주석입니다.

| 항목 | 인식하는 키 (대소문자 무시) | 저장 위치 |
|------|----------------------------|-----------|
| 제목 | `곡 제목`, `곡명`, `제목`, `title`, `name` | `Title` (NFC 정규화) |
| 아티스트 | `아티스트`, `artist` | `Artist` |
| 작사 | `작사`, `작사가`, `lyricist`, `lyrics`, `作詞` | `Lyricist` |
| 작곡 | `작곡`, `작곡가`, `composer`, `作曲` | `Composer` |
| 편곡 | `편곡`, `편곡가`, `arranger`, `arrange`, `編曲` | `Arranger` |
| 채보 | `채보`, `채보자`, `charter`, `譜面`, `譜面制作`, `譜面制作者` | `Charter` |
| 수록 CD | `수록 CD`, `수록 앨범`, `収録CD`, `CD title`, `CD` | `CdTitle` |
| 원작 게임 | `원작 게임`, `원작`, `게임`, `game title`, `game`, `原作` | `GameTitle` |
| 캐릭터 | `캐릭터`, `character`, `artistid` | `Character` |
| 난이도 목록 | `난이도`, `difficulty`, `level` (`,` `，` `|` `;`로 구분) | `Difficulties` |
| 난이도 숫자 | `easy`, `normal`, `hard`, `expert` (숫자) | `DifficultyNumbers` |

아티스트부터 원작 게임까지 7개는 크레딧이며, 값은 NFC로 정규화합니다. 곡 선택 화면의 상세 패널(아티스트·작사·작곡·편곡·채보·
수록 CD·원작 게임)과 곡 시작 화면(작사·작곡·편곡)에 표시하고, 없는 항목은 게임이 정보 없음에 쓰는 `-`로 보입니다
([`CreditTextPatch`](../../GRC2/Harmony/CreditTextPatch.cs), 2026-10-08). 2026-10-08 이전에는 `작곡가`/`composer`를
아티스트로 읽었고 나머지 크레딧은 읽지 않았습니다. 그래서 상세 패널에는 각 크레딧 표의 첫 항목(실제 사람 이름)이,
곡 시작 화면에는 템플릿 곡의 크레딧이 나왔습니다.

예:

```
곡 제목 : shut up
아티스트 : 누군가
작사 : 누군가
작곡 : 누군가
편곡 : 누군가
채보 : 화영왕
캐릭터 : 르호
easy : 3
normal : 6
hard : 9
expert : 12
```

- 곡 목록에 표시되는 제목: `info.txt`가 있으면 `Title`(제목 줄이 없으면 기본값 `custom chart`),
  `info.txt`가 아예 없으면 폴더 이름입니다.
- 공백도 구분자라서 짧은 키 뒤에 단어가 더 붙으면 그 단어까지 값이 됩니다(예: 키 목록에 없는 `게임 제목 : X`는 원작 게임 = `제목 : X`).
  위 표의 키를 그대로 쓰세요.
- **파일은 UTF-8로 저장해야 합니다.** Unity Mono에서는 BOM이 없어도 UTF-8로 읽으므로, ANSI(CP949)로 저장하면
  한글이 깨집니다(알려진 문제 G).
- 캐릭터 값의 쓰임은 [아티스트_ID_기반_시스템_분석.md](아티스트_ID_기반_시스템_분석.md)를 봅니다.

## 스캔과 기본 선택

`SceneDetector.OnInitializeMelon()`에서 한 번 실행됩니다.

1. `ScanAlbums(hwa)`: 하위 폴더 + 루트를 스캔해 `_albums`에 등록하고, 앨범 키 "root"가 있으면 그것을, 없으면
   키 정렬 순서의 첫 앨범을 현재 앨범으로 선택합니다([알려진 문제 C5](../maintenance/알려진_문제.md), 2026-10-08 수정).
2. 곡 정보(`SongInfo`)는 현재 앨범의 `info.txt`에서 옵니다. 없으면 기본값을 씁니다. 예전에 있던 "제목·아티스트로 앨범 다시 고르기"
   폴백은 2026-10-08에 지웠습니다(루트가 기본 앨범이 되면서 도달하지 않는 코드였습니다).
3. 모든 앨범의 모든 BMS를 파싱해 `SceneDetector.ParsedBmsNotesByFile`(전체 경로 키)에 캐시합니다.

앨범을 새로 추가하면 게임을 다시 시작해야 곡 목록에 나타납니다(스캔은 시작할 때 한 번뿐).

## 곡 선택 → 앨범 선택

1. 곡 목록 주입([커스텀_곡_주입_시스템_분석.md](커스텀_곡_주입_시스템_분석.md))이 앨범마다 커스텀 MusicID(54부터)를
   붙이고 `RegisterMusicIDToAlbum()`으로 등록합니다.
2. 곡 선택 커서가 움직이면 `AudioClipPatch`(`noticeChangedMusic` postfix)가 `IsCustomChartMusicID()`로 커스텀 곡인지 보고,
   맞으면 `SelectAlbumByMusicID()`로 현재 앨범을 바꿉니다.
3. 이후 `GetCurrentBmsFile()`, `GetCurrentImageFile()`, `GetCurrentBgaFile()`, `GetCurrentBgmFile()`,
   `GetCurrentSongInfo()`, `GetCurrentMusicID()`가 모두 이 앨범 기준으로 동작합니다.

## 주요 API

| 메서드 | 설명 |
|--------|------|
| `ScanAlbums(path)` | 전체 스캔 + 기본 앨범 선택 |
| `SelectAlbum(folderPath)` / `SelectAlbumByMusicID(id)` | 현재 앨범 변경 |
| `GetCurrent*()` | 현재 앨범의 파일/정보 (없으면 `null`) |
| `GetCurrentMusicID()` / `GetMusicIDByAlbum(album)` | 앨범에 붙은 커스텀 MusicID (없으면 `null`) |
| `IsCustomChartMusicID(id)` | 등록된 커스텀 MusicID인지 |
| `RegisterArtistFirstSong` / `GetArtistFirstSong` | 캐릭터별 첫 원본 곡 |
| `RegisterOriginalTitle` / `GetOriginalTitle` / `GetAllOriginalTitles` | TextPatch용 원본 제목 |
| `GetAllAlbums()` | 전체 앨범 딕셔너리 |

## 주의사항

- 앨범 키는 폴더 이름이라, 이름이 같은 폴더는 있을 수 없습니다(하위 폴더가 한 단계뿐이므로 실질적으로 충돌 없음).
- 커스텀 MusicID는 앨범 순서로 정해져서 폴더를 추가·삭제하면 바뀝니다(알려진 문제 C4).
- BMS가 없거나 노트가 0개인 앨범을 플레이하면 이전 앨범의 차트가 들어갈 수 있습니다(알려진 문제 C2).
  BGA/BGM이 없는 앨범은 원본 BGA/BGM이 나옵니다(C1은 2026-10-04에 수정).
